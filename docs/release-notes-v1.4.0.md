# RAGchat 1.4.0

本地优先的记忆陪聊 App 第五个发行版：模型默认在手机端跑，聊天记录、记忆、人设全部留在本机；想要更强的对话可以切到云端 API。

## 这个版本有什么

- **端上推理**：nobodywho（llama.cpp）在 CPU 上直接跑 GGUF，不走云端
- **长期记忆**：从对话提取事实 / 偏好 / 事件 / 关系，带重要度，可编辑、停用、删除
- **会话持久化**：关掉 App 再打开，最近会话还在；`new` 开新对话时自动整理记忆
- **两个人设槽位**：本地模型用「大肥鱼」短版，云端 API 用长版。点槽位切换后端，两张卡各自保存、互不覆盖
- **人设编辑**：短人设填六项字段，长人设整段编辑；编辑器里能看到当前后端的 system 预算（本地 800 / 云端 6000）
- **采样可调**：温度三档（稳定 0.4 / 平衡 0.6 / 活跃 0.9），即时生效
- **模型可选**：Qwen3.5-9B / 4B / 2B 按机型挑；首次打开可以先「稍后配置」进界面
- **可选云端后端**：DeepSeek（或任意 OpenAI 兼容 API），key 存系统 Keychain/Keystore
- **下载走魔搭**：ModelScope 国内直连，下载器自己实现，支持 >2GB 文件
- **纸页与档案界面**：暖白纸底 + 档案编号 + 只在交互层用玻璃，单一纸墨色
- **导出 / 导入备份**：`.ragchat.zip`（会话 + 轮次 + 记忆 + 人设设置），不含 key 与模型文件

## 1.4.0 新增：情景记忆真的会检索了

以前记忆进上下文只有一条规则——按重要度从高到低塞，塞满 800 token 就停。这个版本开始，**先看你问的是什么**：

- **向量检索**：每条记忆用端上嵌入模型（Qwen3-Embedding-0.6B）算成 1024 维向量，提问时先编码问题，按余弦相似度找相关记忆
- **阈值来自实测，不是拍的**：真机标定得到的噪音地板是 0.385（毫秒无关的四对句子最高也只到 0.3848），所以阈值定在 **0.50**，低于它的一律当噪音
- **命中优先，其余兜底**：命中的排前面，没命中的按重要度垫在后面——检索漏了也不会让记忆变少，预算够就照样装得下
- **后台补算**：记忆写入、备份导入、换模型后自动补向量，不进聊天主路径；嵌入模型没装或加载失败会**静默退回**纯重要度，聊天照旧
- **设置 → 01 / MODEL → 诊断**：
  - 标定：量维度、归一化、相似度分布，报告给出建议阈值（换嵌入模型后跑一次就能重定阈值）
  - 自检：12 道固定问题，比较「纯重要度」与「检索」在同一预算下装进上下文的记忆，看命中率与差异
- 实测开销：每轮提问多 58 ms（9B 本地回答本身约 49 s，可忽略）；备份仍不含向量，导入后按当前模型重算

## 安装

1. 下载 `RAGchat-1.4.0-arm64.apk` 安装（applicationId `com.dannylam.ragchat`，versionCode 2005；只装这一个，别装 x86_64 / armeabi 分裂包）
2. 首次打开在模型准备页选一个聊天模型下载（9B / 4B / 2B）；不想现在下载就点「稍后配置，先进入」
3. 想用向量检索，再去 01 / MODEL 里下载嵌入模型 **Qwen3-Embedding-0.6B**（约 640 MB）；不装也能正常聊，只是回到按重要度排序

模型不打进 APK；也可以电脑 `adb push` GGUF 到 App 私有目录后点「重新扫描」。

## 已知限制

- 9B 模型在手机上首次加载约 40–60 秒，一条长回答实测 49 s；要快就换 2B / 4B
- 情景记忆的检索阈值针对 Qwen3-Embedding-0.6B 标定过；换成别的嵌入模型请先跑一次「标定」，按报告给的阈值改
- 自检的问题集是固定的 12 道通用问题，命中率会随你记忆的内容变化，不代表模型好坏
- 只在 Android 真机（一加 / Android 16，arm64）验证过
