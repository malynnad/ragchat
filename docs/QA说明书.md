# 知识库问答 App · Q&A 说明书

适用版本：2026-11-15 v2 更新版（debug APK，Apple/iOS 风格界面）。主机 74/74 测试绿；真机冒烟进行中。正文面向第一次使用的人，只讲手机操作；电脑相关细节在附录。

---

## 一、开始使用

**Q：这个 App 是干什么的？**
A：把你自己的文档变成一本「可以提问的书」。导入资料后，用中文问问题，它只按你导入的资料回答，答案后面带 [1] 这样的引用标记，点一下就能看到原文出处。资料里没写的，它会明确说「不知道」，不编造。类比：开卷考试，只允许翻你带进考场的书。

**Q：第一次打开要做什么？**
A：会停在「模型准备」页。它需要两个模型：生成模型（负责答问，推荐 Qwen3-8B Q4_K_M）和嵌入模型（负责把文字变成可比较的向量，推荐 Qwen3-Embedding-0.6B）。如果手机里已有 GGUF 文件，页面会自动扫描并指派好角色；确认两张卡片各选了一个文件后，点底部「保存并进入知识库」。之后就不再需要这个页面。

**Q：模型从哪里来？**
A：三种方式：页内「下载」按钮（走国内镜像，有进度条）；「导入本地文件」从手机存储选；或用电脑 adb 推送（见附录 A）。两个文件合计约 5.9 GB，请留足存储。

**Q：没有网能用吗？**
A：能。模型准备好之后，导入、提问、管理全程离线，不上传任何数据。只有下载模型那一步需要网。

## 二、导入文档

**Q：支持什么格式？**
A：PDF、DOCX、TXT、MD、CSV 五种，一次可以多选。

**Q：怎么导入？**
A：底部切到「文档」页，点右上角「+」导入文档，在文件管理器里勾选文件后确认添加。页面上方会出现摄取队列：时钟图标=排队、转圈=处理中、对勾=完成（显示分块数）、红叹号=失败（显示原因）。

**Q：「分类」是什么？怎么用？**
A：给文档贴的标签，比如「历史」「行政」。导入时会弹窗让你选目标分类（默认上次用的）；文档页顶部有分类过滤条，点一下只看该类文档；每份文档右侧菜单可「移动到…」；右上角标签图标可新增/重命名/删除分类。分类只影响检索范围，不影响内容：移动分类不需要重新处理文档。删除分类不删文档，其下文档自动归「未分类」。问答页顶部也能选检索范围：选「历史」就只翻历史类的书。

**Q：「分块」是什么？**
A：App 把每份文档切成一张张「索引卡片」，每张几百字，提问时先挑最相关的几张卡片再组织答案。文档列表里的「N 分块」就是卡片数量。切块是为了让引用能精确到段落，而不是整本书。

**Q：导入要多久？**
A：每张卡片向量化约 2–3 秒。一份几十页的文档可能几分钟。导入期间建议保持 App 在前台、屏幕亮着（见附录 D 的局限说明）。

**Q：导入失败怎么办？**
A：队列里会写明原因。常见是文件损坏、或扫描版 PDF（图片型，没有文字层）。换一份文字版文件重试即可；失败的文件不会留在库里。

## 三、提问与核查

**Q：怎么问？**
A：底部「问答」页，输入框里打中文问题（可多行，最多显示 4 行），点发送。发送后输入框自动清空。你的问题靠右显示成气泡，答案靠左逐字流式出现，问题和答案都留在页面上，可以上下翻看。

**Q：有多快？**
A：点提问后约 3 秒出第一个字，之后大约每秒几个字（实测约 8 token/秒）。一百字的答案十几秒写完。手机性能不同会有差异。

**Q：可以追问吗？它记得上一句吗？**
A：记得（同一个会话内）。问完「故宫是什么时候建的」可以直接追问「它有多大？」，App 会自动把上一问拼进来重新检索，模型也能从上下文理解「它」指什么。右上角显示上下文占用百分比：会话越长占用越高，接近满时会弹窗提示「开启新对话」——不会偷偷忘掉前文。点右上角「+」（新对话）即清空重来。注意：会话不保存，重启 App 后清空；换话题也建议开新对话，省上下文。

**Q：「参考来源」面板是什么？**
A：每条答案下方有可展开的「参考来源 (N)」，列出本轮检索到的全部段落：文档名、相似度分数、原文预览。点任一条可看完整原文。它和答案里的 [n] 互补：[n] 是答案实际引用的，面板是模型看到的全部候选。

**Q：答案里的 [1] 是什么？怎么核查？**
A：引用标记，表示这句话依据第 1 个来源段落。点它，底部弹出「来源 [1]」，显示文档名、分块编号和那段原文，可以逐字核对。答案可能带多个标记 [1][2]…，各点对应各的来源。

**Q：为什么点了引用没反应？**
A：答案还在生成时引用表没就绪，会弹提示「答案完成后可展开引用来源」。等转圈结束再点即可。

**Q：为什么它拒答？**
A：它先算问题与资料的相似度，低于阈值就显示「知识库中未找到相关内容：检索相似度低于阈值，不编造答案。」这是设计行为：书里没写就承认没写。另一种情况是检索到了相近资料但里面没答案，模型也会老实说「资料中未提及…」，同样不编。

**Q：答案不满意怎么办？**
A：先点引用核原文，看是资料没写还是挑错了卡片。挑错卡片可以去设置页调「拒答阈值」或「Top-K」（见第五节），或在问答页顶部切换检索范围（分类）。追问直接问即可；上下文将满或换话题时点「新对话」。

**Q：能中途打断吗？**
A：能。生成期间发送按钮（↑）会变成「停止」，点一下立即停。

**Q：出现「生成失败」红卡怎么办？**
A：先直接重问一次；若反复失败，去设置页点「重新加载模型」，再不行重启 App。红卡上会带具体错误文字，截图发给维护者最容易定位。

## 四、管理文档

**Q：删除一份文档会怎样？**
A：它的全部卡片和向量一起删掉，不可恢复，之后的答案不会再引用它。删除前有确认弹窗，写明「将删除「文件名」及其全部分块与向量，不可恢复。」

**Q：什么时候需要重建索引？**
A：怀疑索引坏了、或换了嵌入模型时。点文档页右上角刷新图标，确认「全量重建索引」。它从保存的原文重新解析、分块、嵌入，文档多时耗时数分钟，期间可以继续浏览。换嵌入模型后设置页会出现醒目横幅「嵌入模型已更换，索引待重建」并带重建按钮——旧向量与新模型不兼容，重建前问答会明确报错提示，不会崩溃。

**Q：想全部清空重来？**
A：设置页底部红色「清空知识库（二次确认）」，两次确认后清空所有文档与卡片。模型文件不受影响，不用重新准备。

## 五、设置项

**Q：怎么换模型？**
A：设置页「模型」卡有两个选择行：生成模型（答问）和嵌入模型（向量化），点一下弹出手机里扫描到的全部 GGUF 文件供选择。选另一个文件会弹确认，确认后自动重新加载（数十秒）。换生成模型后直接问答即可；换嵌入模型后必须重建索引（见第四节横幅提示）。找不到文件时点「重新扫描」。

**Q：「下载候选模型」里有什么？**
A：内置 5 个候选（生成 4B/8B/14B、嵌入 0.6B/4B），走国内镜像，每条标了体积和备注。点云下载图标即下载并自动切换到该模型，有进度条。注意：不支持断点续传，中断需重来；14B 和嵌入 4B 在本机属边缘配置，下载后需实际验证流畅度，不建议日常首选。

**Q：「回答风格」是什么？**
A：四档：默认、通俗讲解（白话 + 比喻）、严谨考据（书面语、逐条引用）、自定义（自己写一句风格要求）。它只调整表达方式，不改变「只按资料回答、不编造」的底线。切换后下一问即生效，不用重新加载模型。

**Q：「拒答阈值 0.30」是什么意思？**
A：相似度是 0 到 1 的分数，1 表示几乎同义。实测相关问题约 0.64、无关问题约 0.17，默认 0.30 落在两者之间。调高（如 0.5）更保守、更容易拒答；调低（如 0.2）更敢答、但可能拿不太相关的资料硬答。滑块即时生效。

**Q：「Top-K 5」是什么？**
A：一次提问最多挑 5 张卡片给模型当参考，也是引用数量的上限。资料杂、答案串味时调小；长文档答案不全时调大。

**Q：「Vulkan GPU 加速」要不要开？**
A：本机实测 CPU 反而更快、更省内存（原因见附录 C），默认关闭，建议保持关。打开或关闭都需要重新加载模型才生效。

**Q：「存储占用」怎么看？**
A：「知识库 DB」是你的文档与向量，通常几十 KB 到几 MB；「模型文件」约 5.86 GB，是大头。单位会自动适配（B/KB/MB/GB），小库不会显示成 0.0 MB。

## 六、常见现象

**Q：提问时手机发热、变慢，正常吗？**
A：正常。8B 模型在 CPU 上满载运算，相当于让手机跑大型游戏。答案写完即恢复。介意发热可缩短问题、调小 Top-K。

**Q：它记得我上一句问了什么吗？**
A：同一个会话内记得（v2 起）：历史纯问答累积在上下文里，追问可解析指代。但会话不写盘：点「新对话」或重启 App 即清空。上下文将满时会提示开新对话，不会自动遗忘。

**Q：模型准备页扫描不到我放的文件？**
A：点「重新扫描」；确认文件是 .gguf 且放在页面显示的目录里（附录 A 有路径与命令）。用「导入本地文件」则不限目录。

- 推荐模型：生成 `Qwen3-8B-Q4_K_M.gguf`（5.23 GB），嵌入 `Qwen3-Embedding-0.6B-Q8_0.gguf`（0.64 GB）。
- 应用内下载源（hf-mirror，国内可达）：
  - `https://hf-mirror.com/unsloth/Qwen3-8B-GGUF/resolve/main/Qwen3-8B-Q4_K_M.gguf`
  - `https://hf-mirror.com/Qwen/Qwen3-Embedding-0.6B-GGUF/resolve/main/Qwen3-Embedding-0.6B-Q8_0.gguf`
  - 注意：下载有进度条但**不支持断点续传**，中断需重头来；失败可重试或改手动导入。
- 模型目录（真机实测）：`/storage/emulated/0/Android/data/com.dannylam.rag_kb/files/models/`。模型准备页的「USB 手动导入说明（国内网络兜底）」展开后也显示该路径。
- adb 示例：`adb push Qwen3-8B-Q4_K_M.gguf /storage/emulated/0/Android/data/com.dannylam.rag_kb/files/models/`，push 完回页内点「重新扫描」。
- 角色指派：扫描后自动按文件名启发式指派（含 embed 的归嵌入，其余最大文件归生成），可用下拉框手动改；「保存并进入知识库」后配置持久化。

## 附录 B：真机性能实测（OnePlus PKR110，骁龙 8 至尊版 / 14.8 GB RAM）

来源：docs/adr/0005-cpu-backend-default.md（nobodywho 6.0.0，debug APK）。

| 项目 | 实测 |
|---|---|
| 嵌入模型加载 | 冷 9.7 s / 热 1.3 s |
| 单块嵌入（1024 维） | 约 2.6–2.9 s |
| 语义区分度 | 相关 cos 0.636 vs 无关 0.174 |
| 生成模型加载 | CPU 3.0 s（GPU 13.4 s） |
| 首 token | CPU 3.2–3.8 s（GPU 5.1 s） |
| 纯解码 | CPU ≈7.7–8.0 tok/s（GPU ≈6.9） |
| 加载后可用 RAM | CPU 7.4 GB（GPU 1.8 GB） |
| 双模型共存 | 通过，共存后仍余 7.4 GB，无 OOM |

## 附录 C：为什么默认 CPU

GPU（Vulkan）会把 5.2 GB 权重拷进匿名内存，可用 RAM 从 7.0 GB 掉到 1.8 GB；CPU 走 mmap，权重留在可回收的文件页缓存里，系统内存紧张时能自动让路。且本机 Adreno 上 Vulkan 各阶段实测均慢于 ARM CPU（i8mm）。故默认 CPU，GPU 仅作开关保留。

## 附录 D：架构与已知局限

- 接缝：RagService 编排；DocumentParser/Chunker 纯 Dart；VectorStore 封装 SQLite（暴力余弦，2–5 万分块规模不需要 HNSW）；ModelGateway 隔离模型库，生产实现 NobodyWhoGateway。
- 质量：74/74 单元/集成/widget 测试绿，分析器零警告；v1 真机冒烟覆盖引用、拒答、删除级联、重建索引、设置页；v2 冒烟（会话、分类、模型切换、风格）进行中。
- 已知局限：下载无续传；摄取无前台服务通知，几百份文档的过夜场景建议保持前台/充电；会话不持久化（重启即清）；上下文占用为保守估算（1 字≈1 token）；每次提问约 3 s 固定开销；PDF/DOCX 的真机导入未进冒烟（主机测试覆盖）。界面已改为 Apple/iOS 风格（Cupertino 底部标签栏 + 导航栏，见 ADR-0008），真机验证标签切换与状态栏避让正常。
