# 会话上下文策略：累积纯 Q/A，资料剥离，满则新对话

> **2026-11-16 修订**（ADR-0009）：第 6 条「不持久化」被取代——陪聊 app 会话写盘（sessions/turns 表），重启恢复；「资料剥离」随 RAG 移除自然消失，纯 Q/A 累积、每轮重建消息表、预算预检、新对话语义全部延续。

v1 为单轮问答（规格书 §4/§6）。2026-11-15 v2 用户要求支持追问，并自定义方案：「单轮对话根据上下文容量，满了提示打开新对话」——即上下文自然累积、不自动遗忘，容量将满时由用户显式开启新对话。

## 状态

accepted

## 决策

1. **Dart 侧持有会话真相**：`List<SessionTurn>` 只存剥离资料后的 question + answer。资料卡（每轮约 2000–2500 字）永不进入历史，否则 8K 上下文两三轮即被塞满，且旧 [n] 标记会错挂到新一轮来源。
2. **每轮重建消息表**：system（RAG 底线 + 回答风格）→ 历史各轮纯 Q/A → 当前轮「资料 + 问题」user 消息；经 `ModelGateway.generate(messages)` → nobodywho `Chat.complete(messages)`（整表替换历史并续写）。删除 v1 的每轮 `resetContext`。
3. **容量预算预检**：纯 Dart 保守估算（1 字符 ≈ 1 token），预留 system/答案/资料余量，安全系数 0.9。预计超 90% → 不发请求，发 `AnswerContextFull` 事件，UI 弹窗引导「开启新对话」。AppBar 常显占用百分比。native 侧 `ContextShiftOptions(enabled: false)` 使上下文满成为显式错误而非静默遗忘，作为兜底。
4. **追问检索兜底**：「它有多长？」单独嵌入会低分拒答。若拒答且历史非空 → 用「上一轮问题 + 当前问题」重嵌重试一次（一次嵌入，无额外 LLM 调用）；仍拒答则诚实拒答。生成侧因历史在上下文里，模型可解析指代。
5. **新对话**：清空会话列表 + `gateway.resetSession()`（`resetContext`）+ 清页，有确认弹窗。
6. **不持久化**：会话历史不写盘，重启即清。知识库（文档/向量）持久化不受影响。

## 后果

- 规格书 §4/§6 的「单轮」条款被本 ADR 取代；CONTEXT.md 术语「单轮问答」改为「会话 / 新对话 / 上下文容量」。
- `complete()` 每轮重建消息表：前缀不变时 llama.cpp 复用 KV 前缀缓存，性能影响预期小；真机冒烟需观察首字延迟是否劣化。
- token 估算是保守近似，90% 阈值留余量；实际可用轮数随答案长度变化（典型 5–8 轮）。
- 拒答轮不进入历史，避免无效轮次占用预算。
- 测试接缝：FakeGateway 记录 `lastMessages`，主机测试断言历史剥离、预检、兜底、hits 返回（session_context_test.dart）。
