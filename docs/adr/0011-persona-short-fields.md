# 人设回到短字段：一个人设、有口癖、够快

2026-11-16 用户否掉 ADR-0010 的自由正文方案：这个 App 只是聊天，人设要「有人味、自然」，但不需要长篇设定；手机端小模型回答要快。参照 `dsh-persona-dafeiyu` 的整段 markdown 不合适——那条 2,300 字的人设 ≈ 2,300 token，是我们 system 总预算（800）的近三倍，而且每轮都要重付一遍，首字延迟直接吃满。

## 状态

accepted

## 决策

1. **单卡不变**（沿用 ADR-0010 决策 1）：只有一张，可编辑、可恢复内置预设，不切换、不新建删除。
2. **回到短字段**：`名字 / 性格 / 说话方式 / 常用的话（口癖）/ 称呼 / 不做的事`，每项 10–80 字封顶，输入超限直接截断。旧自由正文 `text` 只用于读回 ADR-0010 期间存下的数据，不再出现在编辑器里。
3. **口癖单列一项**：`常说：「嗯，我在」` 比一堆形容词更像人，也让小模型有具体的语料可仿。
4. **软上限 240 token**：编辑器显示「人设 ≈ N token / 建议 ≤240」，超出标红。system 800 里给长期记忆留 560 左右；人设写长不拦，但代价可见。
5. **内置三段重写**（小暖 / 小助 / 阿博）：每段 40–60 字，差别落在口癖上，作为「短也能有人味」的样板。
6. **速度取向**：不改生成参数——`enable_thinking: false` 早已在 `NobodyWhoGateway` 关掉；快的第一来源是短 system（更少 prefill）+ 短回答（style 里写「一两句就停」）。

## 后果

- CONTEXT 的人设卡定义改为「名字 + 性格 / 说话方式 / 口癖 / 称呼 / 不做的事」。
- ADR-0010 决策 2、3（自由正文为主体、五要素降级为兼容层）被本 ADR 取代；决策 1、4、6 继续有效。
- 想再快：换更小的模型或更短的历史（新对话）比继续压人设更有效，人设已接近下限。
