# 项目目的从 RAG 知识库转向本地记忆陪聊 App

2026-11-16 用户将目的改为「简化版本地部署 LLM 聊天 app」：聊天 bot 有记忆能力（自动从对话内容筛选提取、本地保存、可导出继承），支持人设，模型更低版本、速度优先。这是用户目标变更，不是技术取舍；所有基于 RAG 目的的决策重新评估。工作空间迁移至 RAGchat，以清理后的 v2 快照为基线重启。

## 状态

accepted

## 决策

1. **RAG 文档管线整体移除**（用户确认）：文档页、解析器、分块器、引用系统、分类、重建索引及相关依赖（syncfusion_pdf / archive / xml）全部删除。旧 `documents`/`chunks`/`categories` 表数据保留不动——代码删、数据留，将来想找回仍有路。
2. **ADR-0001（事实提取记忆）复活为 accepted-with-changes**：当时否决「RAG+事实混合」的理由是「实现复杂度最高」——如今向量库已建过一遍（vector_store 的 schema/迁移/余弦检索模式直接可抄），成本前提已变化。但 MVP 仍从纯事实条目起步，去重用字符 bigram 余弦（文本级），嵌入混合检索（情景记忆）留 v2。
3. **三层记忆结构**：核心记忆（事实条目，常驻注入 system，用户可见可编辑可停用）为 MVP 必做；情景记忆（对话轮次向量化、按问题检索命中才注入）为 v2；工作记忆（当前会话，现有机制延续）。
4. **会话持久化**：ADR-0006 第 6 条「不写盘」修订——陪聊 app 重启丢历史体验不可接受，新增 `sessions`/`turns` 表；记忆生命周期独立于会话。
5. **人设卡升级**：ADR-0007 的风格句扩展为完整人设卡 `{名字, 性格, 说话风格, 对用户的称呼, 边界}`，多卡可切换，预设内置。0007 的教训保留：8B 以下模型指令遵循有限，卡内容百字级、越短越稳。
6. **导出继承**：版本化单 JSON（schemaVersion + 人设卡 + 记忆条目，不含 embedding），按 id upsert、冲突取 updated_at 新者。
7. **模型速度优先**：默认推荐 Qwen3.5-2B Q4（速度档）；嵌入模型在 MVP 中改为可选下载（仅 v2 情景记忆需要）。
8. **消息组装顺序**（每轮重建，延续 ADR-0006 模式）：system（人设卡 → 核心记忆清单按 importance 排序）→ 历史纯 Q/A → 当前问题。人设+记忆预算 ≤800 token，超限仍走 `AnswerContextFull` 引导新对话。

## 后果

- ADR-0001 状态改为 superseded（由本 ADR 复活修订）；ADR-0003 方向被取代；ADR-0006 第 6 条被取代；ADR-0007 扩展为人设卡。各 ADR 头部加注。
- CONTEXT.md 术语表重写，RAG 术语表归档至 docs/archive/CONTEXT-rag-kb.md。
- applicationId 不变：旧 app 的 rag.db / settings.json 经覆盖安装被新版继承，正好作为 v2→v3 迁移的真机验证数据。
- rag.db 升 schema v3：新增 memories / sessions / turns 表，沿用幂等迁移模式。
- 记忆质量依赖小模型提取 prompt 设计（ADR-0001 的教训在新时代依然成立），这是本项目最需要调优的点。
- nobodywho 同一时刻仅加载一个生成模型：记忆提取复用聊天模型，不单独加载。
