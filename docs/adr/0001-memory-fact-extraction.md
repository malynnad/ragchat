# 长期记忆采用事实条目提取，而非 RAG

> **状态：superseded**（2026-11-16，项目转回陪聊方向，见 ADR-0009：本决策复活并修订——事实条目提取成为新目标的核心机制，「混合方案复杂度最高」的否决理由因向量库基建已存在而不再成立；MVP 仍从纯事实条目起步）。前一段历史：2026-11-14 曾随项目转向 RAG 知识库（ADR-0003）被废弃。

聊天程序需要跨对话长期记忆。备选方案有纯 RAG、RAG+事实混合、事实条目提取。用户手机（骁龙8至尊版 + 16GB）跑 RAG 的额外压力经评估可忽略（嵌入模型仅约 100–300MB 内存、毫秒级计算），压力不是决定因素；最终选择事实条目提取，因为人设陪聊场景下"用户叫什么/喜欢什么"这类稳定事实必须可靠命中——纯 RAG 对稳定事实可能漏检，而事实清单常驻注入、可靠且用户可查看/删除/纠正。

## 备选方案

- **纯 RAG**：擅长回忆"聊过什么"的细节，但稳定事实依赖检索命中，且记忆不可见不可管理。用户最初倾向此方案，了解漏检风险后放弃。
- **RAG + 事实混合**：效果最完整，但实现复杂度最高，与"单纯聊天、保持简单"的定位不符。

## 后果

- 记忆质量依赖本地小模型的提取能力，提取提示词需要认真设计。
- 无法回忆未被提取成条目的历史细节；若日后需要，可再叠加 RAG（记忆清单结构不受影响）。
