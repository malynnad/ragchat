# 把当前时间写进 system：小模型分不清早晚

用户反馈：聊到早上还是晚上，模型分不清，「早上/晚上傻傻的」。根因不是模型笨——
**它根本没被告知现在几点**，上下文里唯一的「时间」是聊天记录里的措辞。

## 状态

accepted

## 决策

1. **每轮重建 system 时带上当前时间**，格式是人类口语而不是 `2026-11-28T11:15:00Z`：
   `现在是2026年11月28日 周六 上午 11:14`。包含日期、星期、时段词、12 小时制。
2. **时段词单独算**（`daytimeOf`）：深夜 / 早上 / 上午 / 中午 / 下午 / 傍晚 / 晚上。
   24 小时制小模型要自己换算，给它一个中文词就没有换算这一步。
3. **措辞必须「授权」模型直接回答时间**。第一版只写「现在是 X」，
   deepseek-flash 仍答「我看不了时间」——它把「没有实时信息」当成身份设定。
   改成「这是准确时间，用户问日期、时间、星期就直接回答，不要说不知道」后立刻正确。
   这条是试出来的，别再退回去。
4. **时间行计入 800 token 预算**：`promptHead` 统一产出「人设 + 时间行」，
   `fitMemoriesWithinBudget` 与 `retrieval_eval` 都从它取头部长度，避免截断少算。
5. 时间来自设备本地时区（`DateTime.now()`），注入点可传入固定时间，测试稳定。

## 后果

- 每轮多 ~35 token。云端口径可忽略；本地 800 预算里相当于少装一条短记忆，
  这个代价换「早上知道说早上好」，值。
- 依赖设备时间正确。用户手动改过系统时间时模型会跟着错——不修，也不是它能修的。
- 时间只进 system，不进历史轮次；历史里旧回复不会被改写。

## 验证

真机（Android 16，云端 deepseek-flash）：问 `what time is it now` →
「中午 11:15，周六」，与系统时钟一致。修复前同问题答「本鱼没表，看不了时间」。

测试：`now_label_test` 覆盖时段词边界（0/6/9/12/15/18/21/23 点）、
`nowLabel` 格式与 0/12 点特例、system 含时间行且人设仍在最前、时间行占用预算。
