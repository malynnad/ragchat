# 人设收敛为单卡 + 自由正文

2026-11-16 用手机端本地模型跑 chat 的用户反馈两件事：一是不需要切换人设，只要一张自己写的；二是人设越写越长，每次请求都吃 system 预算，记忆被挤掉。调研参照 `dsh-persona-dafeiyu` 插件（其做法：人设就是一段自由 markdown，整段注入，动态求值免重启）。

## 状态

> 2026-11-16：决策 2、3（自由正文为主体、五要素降级为兼容层）被 ADR-0011 取代——人设回到短字段并新增口癖。

accepted

## 决策

1. **单卡**：App 只保留一张人设，设置页不再有切换/新建/删除，只有「编辑」「恢复默认」。存储层仍按列表存（兼容旧 settings.json 的多卡），保存时收成一张。
2. **自由正文**：`PersonaCard` 新增 `text` 字段，非空即整段写进 system，可放标题、例子、口癖——比五要素拼句表达力强，也方便把现成人设 markdown 直接粘进来。
3. **五要素降级为兼容层**：`personality/style/addressTerm/boundary` 仅用于读旧数据与渲染回落（正文为空时的一句拼句），不再在 UI 暴露。旧版本 App 读回时字段仍在，不至于丢内容。
4. **预算可见**：编辑器显示「人设 ≈ N token / 800」进度条，并提示记忆还剩多少；超过 75% 标红。估算沿用 `estimateTokens`（1 字 ≈ 1 token 保守上界）。
5. **内置三段改成短正文样板**（小助/小暖/阿博，各 60–90 字），既当默认值也当「够短」的示范；编辑器提供「结构模板」按钮生成可删的骨架。
6. **恢复默认**：二次确认后按 id 回填内置预设。

## 后果

- CONTEXT 的人设卡定义由五要素改为「名字 + 正文」；US-22 的多卡验收改为单卡编辑验收。
- ADR-0009 决策 5（多卡可切换）被本 ADR 部分取代，其余决策不变。
- 人设过长仍会被 `buildSystemPromptWithinBudget` 优先保人设、砍记忆——这是既有取舍，预算表把代价显式化，不做自动截断。
- 不做导入/导出文件：手机端粘贴即可；导出继承（US-23）另行实现。
